# 入库扫描器（硬件原型）

这个目录是 [docs/HARDWARE.md](../docs/HARDWARE.md) 的落地部分：一块能「拿起—扫—放下」的
独立设备，把东西扫进账本，不依赖手机一直开着。

```
hardware/
├── README.md            # 你在这里
└── firmware/
    ├── platformio.ini   # ESP32-S3-DevKitC-1 + OV2640 + ST7789
    ├── include/pins.h   # 引脚，与文档 §4.1 一一对应
    └── src/main.cpp     # 取帧 → 解码 → 去重 → 上报 → 反馈 → 休眠
```

## 先说清楚它是什么状态

`firmware/` 是**骨架**，不是成品：

- 能读的部分是完整的：引脚定义、摄像头初始化参数、QR 解码、去重、上报、反馈、休眠策略。
- 缺的部分在 `main.cpp` 末尾逐条列出，最要紧的是 **BLE 配网**——不做这一步，设备没法连接到你的家庭。
- **没有在本机编译过**。这里没有 ESP-IDF 工具链，第一次 `pio run` 必然会遇到几处板子相关的报错
  （最常见的是 PSRAM 模式和 `esp32-camera` 的引脚命名差异）。文档给的是设计依据，不是「已验证」的声明。

## 花 ¥113 把它跑起来

不需要打板，不需要画原理图：

| 件 | 型号 | 价格 |
| --- | --- | --- |
| 开发板 | ESP32-S3-DevKitC-1（N16R8，自带 USB-C） | ¥55 |
| 摄像头 | OV2640 模块（24pin FPC 转 DIP） | ¥15 |
| 屏幕 | ST7789 1.3" 240×240 SPI | ¥18 |
| 杂项 | 面包板、杜邦线、蜂鸣器、轻触按键 | ¥25 |

```bash
cd hardware/firmware
pio run -t upload
pio device monitor
```

第一次跑起来只需要验证一件事：**在你自己家的灯光下，贴纸上的二维码多久能扫出来**。
如果这个数字不能接受（比如超过 800ms），后面所有关于外壳、电池、认证的工作都白做。

## 它和后端怎么说话

只用已经存在的接口，后端一行都不用改：

| 时机 | 请求 |
| --- | --- |
| 开机 | `POST /api/v1/auth/login` |
| 每次扫码 | `GET /api/v1/scan/lookup?code=<原始码>` |
| 未知码建档 | `POST /api/v1/items` |
| 拍照存证 | `POST /api/v1/attachments` |

请求头固定带 `Authorization: Bearer <token>` 和 `X-Family-Id`。

设备用的是**专用成员账号**（`scanner@example.com`，只给 `item.view` / `item.create` /
`item.update` / `doc.upload`）。设备丢了就去「成员」里停用这个账号，家里其他数据不受影响——
这是把「一个没有屏幕锁的终端」放进家里的代价控制住的办法。

## 为什么不用现成的扫码枪

¥80 的蓝牙扫码枪只会「打字」：把码打进当前焦点窗口。要让它进账本，得有一台常开的设备
在前台跑着，而且它不会告诉你「这箱东西上周就登记过」。详见文档 §2.2。
