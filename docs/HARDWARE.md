# 入库扫描器（硬件）

家庭里真正麻烦的一步不是「记」，是「录」。买回来一箱东西，坐下来一件件敲键盘，这件事做过一次就不想做第二次。
所以需要一个拿起来就能扫、扫完就进账本的小设备：**对着条码/二维码按一下，东西就进库了**。

这份文档是它的完整设计：选型、电路、固件、与 HomeLedger 的接口、以及为什么最终落在 ESP32-S3 上。

---

## 1. 结论

| | 方案 | 结论 |
|---|---|---|
| **主推** | **ESP32-S3-WROOM-1-N16R8** + OV2640 + 1.3" IPS + 18650 | 整机 BOM 约 **¥83**（1k 量），握持式，续航以周计 |
| 备选 | ESP32-S3 + OV5640（500 万像素） | +¥6，能拍清快递单做 OCR，扫码速度不变 |
| 升级 | Luckfox Pico Ultra W（RV1106，0.5 TOPS NPU） | ¥70 起，Linux，能跑目标检测做「整箱识别」，功耗与开机时间是代价 |
| 不推荐 | 树莓派 Zero 2 W | 能跑，但贵 3–5 倍、开机 20 秒、待机功耗 10 倍，为一个扫码付这些不值得 |

一句话：**扫码是确定性任务，不需要操作系统**。用 MCU 把这件事做到 200ms 出结果、几个月不用充电，
比用一块 Linux 板子把同一件事做到 1.2 秒、每天充电，更符合「放在玄关、随手拿起来用」的场景。

## 2. 为什么是 ESP32-S3

| | ESP32-S3 | RV1106 (Luckfox) | Pi Zero 2 W | ESP32-CAM |
|---|---|---|---|---|
| 参考单价（1k） | **¥26** | ¥60（带 WiFi 的 Ultra W ¥90） | ¥110–160 | ¥18 |
| 摄像头接口 | DVP 8-bit，2MP 直连 | MIPI CSI 2-lane | CSI（排线） | DVP |
| WiFi | 2.4G 802.11 b/g/n | WiFi 6（Ultra W） | 2.4G | 2.4G |
| 蓝牙 | **BLE 5.0** | BT 5.2（Ultra W） | BT 4.2 | BLE 4.2 |
| 冷启动到可扫 | **~250 ms**（深度睡眠唤醒） | ~8 s | ~20 s | ~300 ms |
| 待机电流 | **20 µA** | ~20 mA | ~120 mA | 20 µA |
| 扫码帧率（VGA QR） | 15–25 fps（quirc） | 30 fps+（zbar/OpenCV） | 30 fps+ | 8–12 fps |
| 能不能做视觉识别 | 不能 | **能**（0.5 TOPS NPU） | 勉强（CPU） | 不能 |
| 维护成本 | 无 OS，固件 OTA | Linux 镜像 + 应用 | Linux 镜像 + 应用 | 无 OS |

三件事决定了选择：

1. **唤醒即用**。入库是「拿起—扫—放下」的动作，冷启动 20 秒的设备不会被用第二次。
   ESP32-S3 从深度睡眠到出结果 250ms，摸到按钮的那一刻已经在工作了。
2. **不用充电**。20µA 待机意味着 2600mAh 电池放三个月还有电；Linux 板子 120mA 待机，一周一充。
3. **确定性**。没有文件系统、没有后台进程、没有 OOM。开机就是扫码，扫不到就是扫不到，不会因为系统更新了一半而变砖。

代价也说清楚：ESP32-S3 **只能读码，不能理解画面**。想识别「这是一箱牛奶」而不是「这箱牛奶上的条码」，
那是 §11 的升级路线，不是这一版要解决的问题。

### 2.1 先别打板：花 ¥130 验证整件事

上面那张表是量产成本。第一次做硬件，正确的顺序是**先让它在桌上跑起来**，再谈 PCB、外壳和电池。

| 件 | 型号 | 价格 |
|---|---|---|
| 开发板 | ESP32-S3-DevKitC-1（N16R8，自带 USB-C 和排针） | ¥55 |
| 摄像头 | OV2640 模块（24pin FPC 转 DIP 小板） | ¥15 |
| 屏幕 | ST7789 1.3" 240×240 SPI 模块 | ¥18 |
| 杂项 | 面包板 + 杜邦线 + 蜂鸣器 + 按键 | ¥25 |
| **合计** | | **≈ ¥113** |

接线就是 §4.1 那张表，一根根插上去。这一步能验证的正是最不确定的部分：**在真实家居光线下，
你的贴纸和商品条码要多久能扫出来**。如果这一步不成立，后面所有的结构、电池、认证都是沉没成本。

跑通之后，再把 §4 的电路画进 PCB——那时候你已经知道自己需要多大的补光、摄像头该朝哪个角度。

### 2.2 为什么不用现成的 USB 扫码枪

京东上 ¥80 就能买到一把 USB/蓝牙扫码枪，看起来更省事。三个原因没走这条路：

- **它只会「打字」**。扫码枪是个键盘，把码打进当前焦点窗口。要让它进账本，得有一台常开的电脑或手机前台运行着——这恰好是「随手拿起就录」想避免的。
- **它不会告诉你结果**。扫到了是「已入库」还是「这箱东西上周就登记过」，扫码枪只会再打一遍字符。屏幕和声音反馈要自己做。
- **它连不上你的局域网**。多数蓝牙扫码枪是 HID，配对给一台设备；换台手机就要重新配对。而我们要的是「设备属于这个家庭，不属于某台手机」。

如果只是想在家里电脑前录入，买一把扫码枪 + 桌面版是最省事的组合，文档不反对。这个设备解决的是另一件事：**离开电脑也能录**。

## 4. 电气设计

### 4.1 引脚分配

| 功能 | GPIO | 备注 |
|---|---|---|
| 摄像头 XCLK / PCLK / VSYNC / HREF | 15 / 13 / 6 / 7 | DVP，8 位数据用 11,9,8,10,12,18,17,16 |
| 摄像头 SDA / SCL（SCCB） | 4 / 5 | 10k 上拉 |
| 摄像头 PWDN / RESET | −1 / −1 | 模组自带，不接 |
| LCD SCLK / MOSI / CS / DC / RST / BL | 21 / 47 / 14 / 45 / 46 / 48 | SPI2，40MHz |
| 按键 `SCAN` | 0 | 兼作 BOOT，低有效，内部上拉 |
| 按键 `PAIR` | 3 | 长按 3s 进配网 |
| 蜂鸣器 | 38 | LEDC PWM |
| WS2812 | 39 | RMT |
| 振动马达 | 40 | MOSFET 低边 |
| 电池电压检测 | 1 | ADC1_CH0，100k/100k 分压 |
| 充电状态 | 2 | TP4056 STAT，开漏 |

> 摄像头与 LCD 共用 SPI？不。DVP 是并口，LCD 走 SPI2，两者不冲突，但**摄像头数据线要远离 LCD 的 SCLK**，
> PCB 上把 DVP 走线排在板子一侧、SPI 走另一侧，中间用地铺隔开。OV2640 在 10MHz XCLK 下对串扰很敏感。

### 4.2 电源树

```
USB-C 5V ──TP4056──┬── 18650 (3.0–4.2V) ──ME6211── 3.3V ── ESP32-S3 / LCD / Camera
                   └── 充电指示
```

- 峰值电流 380mA（WiFi 发射瞬间 + 摄像头 + 背光），ME6211 的 500mA 有 30% 余量。
- 电池低电保护由 DW01A 做，固件另在 3.5V 时提示、3.4V 时拒绝开机（避免锂电过放）。
- 背光串 33Ω 限流，PWM 调光；默认 40% 亮度，省电且室内够看。

### 4.3 功耗预算

| 状态 | 电流 | 2600mAh 可用时长 |
|---|---|---|
| 深度睡眠（等按键） | 20 µA | ~5 年（自放电主导） |
| 待机（WiFi 连接、屏幕熄灭、modem-sleep） | 26 mA | ~4 天 |
| 连续扫码（摄像头 + 解码 + 屏幕） | 210 mA | ~12 小时 |
| 峰值（WiFi 发射） | 380 mA | — |

实际使用：一天扫 30 次，每次 3 秒 → 每天约 0.6mAh，**两个月充一次**。
固件默认 90 秒无操作即断 WiFi、熄屏，300 秒进深度睡眠。

## 5. 结构与交互

```
        ┌──────────────────┐
        │   ◉ 摄像头        │   ← 顶部，向下 15° 出光
        │                  │
        │  ┌────────────┐  │
        │  │  1.3" 屏    │  │   ← 扫完立刻显示：品名 / 位置 / 新入库
        │  └────────────┘  │
        │                  │
        │   [扫描]  [配网]  │   ← 拇指位，凸起 0.6mm，盲按可辨
        └──────────────────┘
              55 × 92 × 21 mm，约 96g
```

- **单键主流程**：按一下 = 扫码；按住不放 = 连续扫（每 1.5 秒一次，用于一箱东西）；长按 3 秒 = 配网。
- **反馈三通道**：蜂鸣（成功一声短、失败两声长）+ 灯（绿/红/蓝呼吸=配网中）+ 振动。
  入库常在储物间，光线暗、戴手套，所以声音和振动是主通道，屏幕是辅助。
- **磁吸背板**：可以吸在冰箱或货架上当固定扫码台，也可以取下来手持。
- 外壳预留 2 个 M2 沉头孔，可上墙。

## 6. 固件

### 6.1 任务划分（FreeRTOS）

| 任务 | 优先级 | 栈 | 职责 |
|---|---|---|---|
| `ui` | 3 | 4 KB | 屏幕刷新、灯效、按键消抖 |
| `scan` | 4 | 8 KB | 取帧 → 灰度 → quirc 解码 → 去重 |
| `net` | 2 | 8 KB | WiFi 管理、HTTP 请求、离线队列重放 |
| `power` | 1 | 2 KB | 电量、息屏、深睡判定 |

`scan` 与 `net` 通过一个深度 8 的队列解耦：扫到就入队，网络慢不挡下一次扫描。

### 6.2 扫码流水线

```
OV2640 (VGA, RGB565) → 灰度化 (PSRAM) → 直方图均衡 → quirc 解码
     ↓ 失败
  中心区域裁剪 (320×320) 再解一次        ← 远距离小码时命中率提升明显
     ↓ 失败
  提高曝光 + 补光 LED，重试 2 帧
```

- VGA 一帧解码 **25–40 ms**，端到端（按下到响）约 **180 ms**。
- 支持 QR / EAN-13 / EAN-8 / Code128 / Code39（quirc 只管 QR，条码用 `zbar` 的 MCU 移植版或自写 EAN 解码器；
  建议直接用 `esp32-camera` + `quirc` + `zxing-cpp` 的精简 C 移植，二进制约 90KB，放得下）。
- **去重**：同一个码在 1.5 秒内只上报一次；不同码立即上报。

### 6.3 OTA 与恢复

- 双分区 OTA（`ota_0` / `ota_1`），新固件校验 SHA256 + 版本号回滚保护。
- 长按两个按键 8 秒 → 进入 USB 烧录模式（ESP32-S3 内置 USB-Serial-JTAG，不需要 CH340）。
- NVS 里保存：WiFi 凭据、服务器地址、账号、令牌、设备 ID、离线队列。
  令牌失效时用保存的账号重新登录，不需要重新配网。

### 6.4 看门狗与失败姿态

- 任务看门狗 15 秒；`net` 卡死不影响 `scan`，屏幕照样显示「已扫描，待上传」。
- 连续 5 次上传失败 → 灯变琥珀色慢闪，**不弹任何东西**（这设备没有弹窗能力，也不该有）。

## 7. 配网

### 7.1 流程

1. 长按 `PAIR` 3 秒 → 屏幕显示 6 位配对码，蓝色呼吸灯，BLE 广播 120 秒。
2. 手机 App（或系统蓝牙设置）连上，写入 WiFi SSID/密码 + 服务器地址 + 配对码。
3. 设备连 WiFi → 用配对码向服务器换取一个**专用账号的令牌**（见 §8.1）→ 屏幕显示「已连接」。
4. 120 秒内没完成 → 自动退出，回到待机。

### 7.2 BLE GATT

| UUID | 属性 | 内容 |
|---|---|---|
| `0000fe00-0000-1000-8000-00805f9b34fb` | Service | 配网服务 |
| `...fe01` | Write (MTU 247，分包) | 配网 JSON：`{"ssid","pass","server","code","name"}` |
| `...fe02` | Notify | 状态：`connecting` / `wifi_fail` / `auth_fail` / `ok` / `error` |
| `...fe03` | Read | 设备信息：型号、固件版本、MAC、电量 |
| `...fe04` | Write | 开始/结束配网窗口（`{"open":true}`） |

### 7.3 安全边界

- BLE 用 LESC + DisplayOnly，配对码就是屏幕上那 6 位；窗口只有 120 秒且必须物理按键触发。
- 设备**不保存 WiFi 密码的明文回显**，也不提供「读取当前 WiFi 密码」的特征值。
- 服务器地址只允许 `http://` 局域网地址；填公网地址时设备会拒绝并在屏幕提示——
  这台设备的设计前提是「在家里用」，允许它连公网等于把家庭账本暴露在一个没有屏幕锁的终端上。

## 8. 与 HomeLedger 的接口契约

固件只依赖已经存在的 HTTP 接口，不需要后端为它加任何东西。这一点是刻意的：
**设备是客户端，不是特殊公民**。它坏掉、被替换、被卖掉，都不影响账本。

### 8.1 账号模型

配网时用的是一个**专用成员账号**，例如 `device@example.com`，角色 `member`，只勾选：

| 权限 | 为什么 |
|---|---|
| `item.view` | 扫码要能查到东西 |
| `item.create` | 扫到不认识的码要能建档 |
| `doc.upload` | 拍张照存证 |
| `item.update` | 标记「已入库」 |

不给删除、不给改成员、不给导出。丢了这个设备，去「成员」里停用这个账号即可，全家其他数据不受影响。

令牌 14 天过期，设备在收到 401 时用保存的账号密码重新登录（密码存在 NVS 的加密分区，
密钥由芯片 efuse 派生的 flash 加密密钥保护——ESP32-S3 支持，量产时开启）。

### 8.2 端点

| 时机 | 请求 |
|---|---|
| 开机 / 令牌过期 | `POST /api/v1/auth/login` |
| 每次扫码 | `GET /api/v1/scan/lookup?code=<原始码>` |
| 扫到未知码，用户确认建档 | `POST /api/v1/items` `{name, barcode, code?, status:"in_use"}` |
| 拍照存证 | `POST /api/v1/attachments`（multipart，`item_id` + `kind=photo`） |
| 断网检测 | `GET /api/v1/system/health`（不需要令牌） |
| 离线补传 | 重放上面的 lookup / create |

请求头固定带 `Authorization: Bearer <token>` 和 `X-Family-Id: <配网时写入的家庭 ID>`。

### 8.3 离线队列与幂等

设备可能在地下室、电梯里、或者家里 WiFi 正好重启。队列设计：

- NVS 环形缓冲 **512 条**，每条 `{uuid, code, at, photo_ref}`，约 40KB。
- 重放时**先 lookup 再决定要不要 create**——这让「重复上传」天然幂等，不需要后端支持幂等键。
- 队列满 → 丢弃最旧的「纯查询」记录，保留「新建」记录（前者可以重扫，后者代表一次真实动作）。
- 照片单独存 PSRAM/Flash 分区，最多 8 张，超了丢最旧并标记 `photo_missing`。

### 8.4 扫码结果怎么用

设备只负责「这是哪个码」，业务判断留在服务器：

```
扫到 HL-000123  → 已知，屏幕显示「戴森 V12 / 储藏室 第二层」
扫到 6901234567892 → 未知条码，屏幕显示「新建？[按一下确认]」
扫到 HL-000123 但已借出 → 屏幕显示「借给 老王，10 月 20 日」
```

这条边界很重要：设备端不做任何业务规则，规则改了不用给设备推固件。

## 9. 和「入库」流程的配合

理想的入库动作：

1. 快递拆箱，东西堆在桌上。
2. 拿起扫描器，按住不放，逐个扫包装上的条码。每扫一个：哔一声，屏幕显示品名和位置。
3. 没条码的东西（比如散装收纳盒）：扫一下自己打印的二维码贴纸，或者按一下「新建」，用摄像头拍一张，
   在手机上补名字（设备不支持输入中文，这是它唯一做不了的事）。
4. 全部扫完，放回磁吸底座。设备在后台把队列发完，灯变绿。

一天 20 件东西，从 25 分钟敲键盘变成 3 分钟扫。

| 电池 | 充电电流 0.8–1.0A，STAT 引脚翻转正常 |
| 按键 | 两次按下，消抖后各触发一次 |
| 固件 | 版本号、MAC、设备 ID 写入并回读一致 |

治具：一块带 pogo pin 的底座 + 一个固定 QR 码牌 + 一个 USB 集线器，PC 端跑 Python 脚本（复用 `backend/app` 的测试夹具）。

### 10.2 认证

- 自用：不需要。
- 送人/售卖：WiFi + BLE 需要 **SRRC**（中国）或 FCC/CE；电池需要 UN38.3 运输鉴定。
  这两项是「从能用到能卖」之间最容易被低估的成本，预算 2–4 万元、2–3 个月。

## 11. 升级路线

| 版本 | 硬件 | 能多做一件什么事 | 成本 |
|---|---|---|---|
| v1（本文） | ESP32-S3 + OV2640 | 读码 | ¥83 |
| v1.5 | 换 OV5640 | 拍清快递单，服务端 OCR 自动填名字 | +¥6 |
| v2 | RV1106（0.5 TOPS NPU）+ MIPI 摄像头 | 整箱识别：不扫码也能认出「这是牛奶」 | ¥150 起 |
| 固定式 | RV1106 + 称重传感器 + 常电 | 柜门开关触发、拿走什么自动记账 | ¥260 起 |

v2 的价值不在「更准地扫码」，而在**把扫码这一步也省掉**。但它需要训练一个家庭物品分类模型，
而且误识别会让账本变脏——所以它是 v1 跑通、数据攒够之后的事，不是现在的事。

## 12. 已知取舍

- **不做中文输入**。设备上没有键盘，命名必须回到手机。这是刻意的：加一个输入法会让 BOM 涨 ¥15、
  固件复杂度翻倍，而「扫完在手机上补个名字」只多花 5 秒。
- **只支持 2.4G WiFi**。ESP32-S3 没有 5G。家里如果 2.4G 和 5G 同名同密码，通常没问题；
  如果只开了 5G，配网会失败，屏幕会明确提示「找不到 2.4G 网络」。
- **不存业务数据**。设备只有队列，没有本地账本。断网太久（>512 条）会丢最旧的查询记录。
  这是为了让它永远不需要「同步冲突解决」这套东西。
- **屏幕小**。1.3 寸 240×240 只够显示 8 个汉字。够用，但不要指望在设备上浏览。

## 13. 下一步

1. 打样：嘉立创 5 片 PCB + 立创商城配单，约 ¥600，两周到货。
2. 固件骨架：`esp-idf` + `esp32-camera` + `quirc`，先把「扫到 → 屏幕显示 → HTTP 上报」跑通。
   仓库里已经有一份可直接 `pio run` 的骨架：[`hardware/firmware/`](../hardware/README.md)，
   包含引脚定义、摄像头参数、QR 解码、去重、上报与休眠策略；BLE 配网是它唯一缺失的硬骨头。
3. 配网：NimBLE + 上面的 GATT 表，用一个网页版 BLE 客户端先验证协议，不必等 App。
4. 结构：Fusion 360 画壳，先 3D 打印验证握感和摄像头视角。
5. 与账本联调：直接对着 `docker compose up` 起的网关跑，用现有接口，不改后端。

> 骨架没有在本机编译过——这里没有 ESP-IDF 工具链。它的价值是把设计落成可读的起点，
> 而不是一个「已经验证可用」的承诺。诚实标注在这里，比让你在第一次 `pio run` 时报错更省时间。
